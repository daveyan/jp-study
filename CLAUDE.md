# JP Study

A personal Japanese study app. Static HTML/CSS/JS with no build step, no bundler and no framework, hosted on GitHub Pages at https://daveyan.github.io/jp-study/ (pushing to `main` deploys).

The site is personal and should stay out of search engines: keep the `<meta name="robots" content="noindex, nofollow">` tag in `index.html`.

## What the app is

- Tabs: **Today** (dashboard), **Vocab** (694 N5 + 641 N4 + 1,405 N3 words, 2,740 in all, spaced repetition), **Grammar** (58 N5 + 79 N4 lessons, covering every point on Bunpro's N5 and N4 lists, plus 10 N3 lessons so far, for the first 10 points of the JLPT Sensei N3 list: Bunpro had no N3 list to use).
- **Kanji** (the 2,138 kanji tagged Jōyō in KANJIDIC2, of which the N5 (56) and N4 (177) ones come first; spaced repetition plus a reading quiz) is on: `SHOW_KANJI` in `app.js` controls its tab, its Today row and its due count, and setting it to `false` hides them again. Readings, meanings, grades and stroke counts come from KANJIDIC2 and example words from JMdict (both EDRDG, CC BY-SA 4.0), credited on the Kanji tab. The official list is 2,136, so KANJIDIC2 has two more; which two is not yet checked (卄 and 朕 are suspects).
- The learner is around N5–N4 and already knows kana and the basics.
- **How they like to study:** they skim, and they have a strong memory, so grading self-tested cards and taking quizzes doesn't teach them much. Reading lots of example sentences in context does. Favour volume of natural examples over drills. They asked for SRS **reading assignments, not quizzes**: vocab and grammar reviews are reading feeds with no grading (see "Reading reviews" below), and the vocab and lesson quizzes were removed. Don't add graded drills back without asking.

## Files

- `index.html`: the page shell. It loads Google Fonts and `style.css`, then **classic** `<script>` tags in this order: `data.js`, `pitch.js`, `grammar-n5.js`, `grammar-n4.js`, `grammar-n3.js`, `app.js`. Load order matters.
- `style.css`: all styles. The first four rules are the base reset that used to come from the Artifact skeleton. Keep them.
- `data.js`: `VOCAB` and `KANJI`. It also documents the sentence markup.
- `pitch.js`: `PITCH['v:'+written form] = [[reading, [downstep, ...]], ...]` (a word with two accent phrases splits its reading with a space and gives a list per alternative: 役に立つ is `["やくに たつ",[[2,1]]]`) for 2574 vocab words (N5, N4 and N3), from Kanjium's accent data plus English Wiktionary for 15 words Kanjium lacks (both CC BY-SA 4.0, so this file stays under that license; keep its header and the credit on the Vocab tab). Counters and words with no usable entry in either are left out rather than guessed (the build script prints them). After adding vocab, run `python3 -I tools/build_pitch.py`: it reads `tools/kanjium/accents.txt` (a copy of Kanjium's data; see the README there), keeps existing entries, and applies the hand-picked values in its `MANUAL` and `WIKTIONARY` tables. `pitchHtml()` in `app.js` draws it (line over high morae, ticks at the rise and drop, an empty slot for a following particle) on vocab list rows, word pages and the lookup sheet.
- `grammar-n5.js` defines `GRAMMAR`; `grammar-n4.js` and `grammar-n3.js` append to it with `GRAMMAR.push(...)`. The top-level `const`s in these classic scripts are shared globals that `app.js` reads.
- `app.js`: everything else, wrapped in an IIFE.
- `manifest.json`, `sw.js`, `icons/`: home-screen install and offline support. `sw.js` serves site files network-first (fresh pushes show on the next load) with the cache as the offline fallback; Google Fonts are cache-first. Add any new site file to `SHELL` in `sw.js`.
- `tools/check_content.py`: content checker (see below). It isn't loaded by the site. `tools/content.py` holds the shared loaders for the analysis scripts.
- `tools/check_coverage.py` (needs `fugashi` and `unidic-lite`): lists content words in vocab examples that VOCAB doesn't teach. `tools/check_register.py`: flags pairs whose polite and casual lines don't differ only in register. Both are reports; they don't change content.
- `tools/add_vocab_examples.py`: appends example sentences to words already in VOCAB (`X=[(jp, [(polite, casual, English), ...])]`).
- `tools/smoke_test.py` (needs `playwright`): drives the app in headless Chromium from a subpath, see **Checking changes**.
- `tools/n5_plan.json`, `tools/n4_plan.json` + `tools/add_vocab_batch.py`: the curated N5 and N4 word lists (readings, BCCWJ ranks) and the script that appends vocab in batches (`B=[(jp, meaning, group, [(polite, casual or None, English) x5]), ...]`). Words from the N4 plan get the `'N4'` level tag. `tools/build_word_plan.py` builds a plan from an elzup/jlpt-word-list CSV and the BCCWJ frequency lists.
- `tools/add_grammar_lessons.py`: adds grammar lessons from a batch file (`L=[dict(id, level, title, sub, pattern, notes, ex=[(polite, casual, English)], quiz=[(q, [right, wrong×3], why)])]`) in the grammar files' style. With `after` it inserts after that lesson; without it, it appends to the level's file. `X=[dict(id, notes, ex)]` appends notes and examples to an existing lesson.
- `tools/bunpro_map.json` + `tools/order_grammar.py`: the map lists Bunpro's 317 N5/N4 grammar points in Bunpro's order, and the N3 points from JLPT Sensei's list (`source`: `jlptsensei`, no Bunpro number), each with the lesson that teaches it. The order script sorts lessons by their first mapped point, sets each lesson's level from that point, and writes N5 lessons to `grammar-n5.js` and N4 lessons to `grammar-n4.js` (the app lists lessons in file order, grouped by level). `EXTRA` places the two lessons with no Bunpro point. After adding a lesson, map its points in the JSON and run the order script.

Every path is relative (no leading `/`), so the site works from a subpath.

## Content

- `VOCAB`: rows of `[written form, reading, meaning, group, [[polite example, translation, casual example], ...], rank]` plus a trailing `'N4'` or `'N3'` for N4 and N3 words, mapped to `{id:'v:'+jp, jp, kana, en, tag, ex:[{jp, en, cas}], rank, lv}`. N4 words show an N4 badge, and the Vocab tab has N5/N4 filter chips. Readings joined with ・ are alternatives (十: じゅう・とお). A leading ～ marks a counter or suffix (～本); its examples only need to contain the form inside the highlight. `rank` is the word's BCCWJ frequency rank (0 if unmatched). Rank ≤ 1000 shows a **Top 1000** badge and filter on the Vocab tab, and "Learn new" picks N5 words before N4, most frequent first within each level (`byLearnOrder`).
- **Sources:** the N5 and N4 word lists are Jonathan Waller's JLPT lists (tanos.co.uk, CC BY) via github.com/elzup/jlpt-word-list (MIT). Frequency ranks come from NINJAL's BCCWJ short-unit and long-unit lemma frequency lists (free for educational use), counted per lemma. The Vocab tab credits both; keep that line. The meanings and all example sentences are written fresh, not copied. Each word has 5 examples (the 30 top-ranked content words added by `add_vocab_examples.py` have 7), and each version of an example highlights the word exactly once. The N3 words (1,405 in all) come from two lists: the 286 N3-list words the example sentences first used (from elzup's list, which mixes N1–N3 tags), and Langoal's N3 list (langoal.com, 1,303 entries) for the rest. Neither has BCCWJ ranks, so no N3 word shows the Top 1000 badge. Pitch for じゃあ, それで, それに, お金持ち and もうすぐ are guesses (the GUESSED table in `tools/build_pitch.py`).
- `KANJI`: rows of `[kanji, meaning, on'yomi, kun'yomi, strokes, [[word, reading, meaning], ...]]`, mapped to `{id:'k:'+ch, ch, en, on, kun, st, ex}`. These words are plain text without markup.
- `GRAMMAR`: objects `{id, level:'N5'|'N4', title, sub, pattern, notes:[html], ex:[[polite sentence, translation, casual sentence], ...], quiz:[{q, o:[4 options], a:correct index, why}]}`. `ex` is the lesson's sentence pool (at least 15 per lesson; every lesson currently has 30 or more). Each feed session shows 10 of them (`FEED_N` in `app.js`), sentences not yet read this round first, so three sessions cover a 30-sentence pool. The lesson page shows five random examples, picked when the lesson is opened, with the rest behind a "Show the other N" toggle. The `quiz` arrays are kept in the data but no longer shown.
- **Polite and casual versions:** every example is stored polite-first (です/ます) with a casual (plain-form) version as its third string, and each line is shown with a tag (formal / casual / English). `settings.order` (e.g. `['pol','cas','en']`) sets the line order and `settings.off` lists hidden lines, set from **Example lines** on the Today tab; at least one Japanese line always stays on. `exLines()` in `app.js` renders them everywhere. With English hidden, the reading feed's Space goes straight to the next sentence. The learner studied polite forms first and wants both to practise switching. Keep the two versions parallel so only the register changes (です→だ, 食べます→食べる, ませんか→ない？, てください→て, ている/ちゃう contractions where natural). Leave the casual string out only when a sentence reads the same in both registers. `ex` strings in the grammar files must be double-quoted JSON, because the checker parses them as JSON.
- **Sentence markup** (vocab and grammar examples only): `{漢字|かんじ}` is ruby (every kanji must be inside one) and `[…]` marks the highlighted word or grammar point. Okurigana stays outside the braces: `{食|た}べる`. Jukujikun readings go on the whole word: `{今日|きょう}`.
- After editing content, run `python3 tools/check_content.py`. It fails on malformed markup, kanji without readings, vocab examples that don't highlight the word, grammar examples with no highlight, or a lesson in `bunpro_map.json` that doesn't exist. It also lists bases that appear with more than one reading, so you can check they're intended.
- The sentences were written by Claude. The learner may flag ones that sound unnatural; fix those when asked.

Card and lesson IDs are keys for saved progress (`'v:'+written form`, `'k:'+kanji`, `g1`…`g13`, `n5-…`, `n4-…`). Never rename them; add new items instead.

- **Navigation & Ergonomics**: clicking the brand (`学 JP Study`) in the header returns to the Today tab from any view (study session, reading feed, quiz, or other tabs). Vocab items open into a dedicated word view with audio, SRS status, Previous/Next navigation, and full example sentences, matching the Grammar and Kanji detail pages. Word and lesson pages share a layout: actions, then a Previous/Next row that steps through the filtered list (wrapping), then a status line with a colored dot. Both take ←/→, K (known) and Esc; the word page also takes R/S for audio. The Grammar tab has the same kind of toolbar: a search over each lesson's title, description, pattern and notes, progress chips (Not started, In progress, Done, Known) and N5/N4 chips (`ui.gq`, `ui.gf`, `ui.glv`; `lessonListHtml()`). Vocab and grammar search support romaji input (transliterated to hiragana and katakana) without switching system IMEs. Kanji review cards can be tapped on mobile touchscreens to reveal answers. Kanji sessions and reading feeds support key `R` or `S` to replay Japanese audio hands-on-keyboard. Hidden furigana has expanded touch hit areas for one-handed phone use. Horizontal swipes: in a reading feed, left reveals the English and then advances; on a kanji card, left reveals it; on a word page, left and right go to the next and previous word; on a lesson page, they browse to the neighbouring lesson without adding it to the Mixed reading pool (only tapping a lesson open does that). Closing a word, lesson or kanji page restores the list's scroll position. **Audio autoplay** (`settings.autoSpeak`, Today tab) speaks when a kanji card is revealed and when each feed sentence appears. Export uses the share sheet where the browser can share files, and falls back to a download.

## State and storage (`app.js`)

- Progress is stored in `localStorage` under `jp-study.progress.v1` in the shape `{v, updatedAt, resetAt, cards, grammar, known, log, flags, settings:{recall, furi, order, off, autoSpeak, spread, listen, rate, goal}}`. `commit()` saves after every change.
- `S.grammar[id]` = `{best, tries, done, read, at, seen, rounds}`. Opening a lesson from the list creates the entry, which adds the lesson to the **Mixed reading** pool (browsing with Previous/Next, arrow keys or swipes doesn't). `read` is the furthest sentence reached in a feed session (out of 10). Finishing a session sets `done` and puts the lesson on the reading schedule (`S.cards[lesson id]`); `best`/`tries` are left over from the removed quiz. `seen` lists the example indexes read in the current round and `rounds` counts completed passes through the whole pool; the lesson page shows them as "12 of 30 sentences read". `at` is updated whenever one of the lesson's sentences is read, in its own feed or in Mixed reading.
- **Grammar progress** (`gstate`): not started, in progress, done or known. The Grammar tab and the Today grammar row share its stack bar (`gStackBar`); the Grammar tab also has a legend, like Vocab.
- **Mixed reading** (`readMix`): 20 sentences from opened or known lessons, weighted toward lessons not read for a while (weight 1 + days since `at`, up to 30), at most 3 per lesson once 7 or more lessons are open.
- **Known items**: `S.known` maps a vocab, kanji or grammar id to `{on, at}`. Known items are skipped by `dueIds`/`newIds`, count as status `known` (`stateOf(id)`), and known lessons count as done (`lessonDone`). Unmarking keeps any existing card, so its schedule resumes. Entries are flipped to `on:false` rather than deleted so `merge()` resolves by `at`. You can mark items via Mark known mode on each tab, the per-item toggle, vocab's bulk "mark all shown" (respects search and filter), and "I already know this" (key K) in study sessions.
- **Backup** (Today tab): Export downloads the whole state as `jp-study-backup-<date>.json`; Import runs `merge()` on the file and what's here, so nothing current is lost.
- **Flagged sentences**: the flag button on any example (vocab list, cards, feeds, lesson previews) toggles `S.flags[polite sentence] = {jp, cas, en, src, on, at}`. The Today tab copies the list as plain text for the learner to paste into a session. When they do, fix those sentences, then they can clear the list.
- **Vocab reading** (`readVocab`): a 20-sentence feed, one sentence per word, from words that are started or known, topped up to 40 words with the most frequent new ones. Buttons are on the Vocab tab and the Today vocab row. It's free reading and doesn't touch the schedule.
- **Reading reviews** (`startReview(kind)`, kind `'vocab'`, `'grammar'` or `'all'`): the SRS for vocab and grammar, run as a reading feed with no grading. Each due word gets `REVIEW_WPER` (3) sentences, ones not shown at its previous review first (`card.exi`, a list of indexes; older saves hold a single number); each due lesson gets `REVIEW_GPER` (5), unread ones first; at most `REVIEW_V` (10) words and `REVIEW_G` (3) lessons per feed, and the end screen offers the rest. In every feed a word's meaning in the card label stays hidden until the English is shown. Reading past an item's last sentence (`fin`) schedules it as Good (`reviewPass`). **See again soon** (key A) schedules it as Again and appends one more of its sentences to the feed; **I already know this** (K) marks it known and drops its other sentences (`knowRead`). Lessons are scheduled in `S.cards` under their lesson id once one of their feeds is finished; a lesson finished before this existed has no card and counts as due (`gCard`, `dueLessons`). Reading a due lesson's own feed to the end also counts as its review. **Learn new** (`startLearn`) is a feed of 5 new words, 2 sentences each, and each word's card is made at its last sentence. **Review order** (`settings.spread`, Today tab, default on = Mixed): `orderUnits()` spreads each word's and lesson's sentences through the feed, picking the next sentence from a random unit weighted by sentences left and never the unit just shown unless it's the only one left; Grouped (off) keeps each unit's sentences together. A See again soon sentence goes to a random later spot not next to the same item (`insertLater`).
- **Lookups as feedback** (`noteTap`): tapping a word in any reading feed, if the word has a card and isn't known, sets `card.tap`; if the card was due after tomorrow it moves to tomorrow. The word's next review pass then counts as Hard instead of Good, and `reviewPass` clears the flag. The lookup sheet says "Looked up: comes back sooner" and also shows two of the word's other sentences (`lookupExamples`), never the one on screen.
- **Daily goal and load** (`settings.goal`, 30/60/100 sentences, default 60): Today shows a progress bar from today's activity log (`goalHtml`). `loadSoon()` estimates the sentences in reviews due by the end of tomorrow (3 per word, 5 per lesson); when it reaches the goal (`heavy()`), Learn new turns into a quiet "Learn anyway" button with a note, and review end screens stop offering new words. The Last 14 days panel also shows totals (`totalsHtml`): sentences read in all, words met (with a card or known), lessons opened.
- **Listen first** (`settings.listen`, only with a Japanese voice): in every reading feed each sentence plays with its text hidden (`ui.read.heard`); Space, a left swipe or "Show Japanese" shows it, then the English (`readStep`). Toggled on Today or in a feed (button, key L). Feeds speak the first Japanese line that is shown (`feedAudio`). **Speed** (`settings.rate`: 0.7 / 0.9 / 1.1) sits under the Voice picker and applies to all audio. Buttons: "Read N due" on the Today rows and tabs, plus "Read everything due" on Today when both words and lessons are due. The old graded card session (`startSession`, Again/Hard/Good/Easy) is used only by the hidden Kanji tab, as is the kanji reading quiz.
- **Furigana** (`settings.furi`): `'auto'` (default) shows readings only over kanji the learner doesn't know yet (a kanji counts as known once a vocab word containing it is marked known or has a mature card; a known or mature kanji card also counts). `'on'` always shows them, `'off'` never does. Hidden readings keep their layout space and can be tapped to show (`ruby.fh`, toggles `.fs`).
- **Reading feed** (`ui.read`): one sentence at a time, 10 sentences each time a lesson's feed starts. The label at the top of each card (word or lesson) opens that word or lesson page; its back button then says "Back to reading" and returns to the same spot in the feed (`ui.back`). Space reveals the English, then moves to the next sentence; → skips ahead. Each sentence read counts toward the activity log, the same as a kanji card or quiz answer.
- **Word lookup**: in every example sentence, words found in `VOCAB` are wrapped in `<span class="lk">` by `jpHtml()`. Tapping one opens a sheet fixed to the bottom of the screen (`#lk-sheet`, outside `#main`) with the reading and pitch, meaning, level, status, and Play audio / Add to reviews / Open word (Open word is hidden during kanji sessions and quizzes). It also shows that word's hidden furigana. Matching (`lookupIndex`, `lookupSegs`) is longest-first on ruby/character boundaries: written forms with kanji, katakana words, the noun part of する verbs, verb and い-adjective stems followed by kana an inflection can start with, and hiragana spellings of 4+ characters for non-verbs (おいしい). A ます-stem noun followed by a verb ending reads as the verb (休みます → 休む), and kana words right after て/で are skipped (てください). About 97% of vocab examples resolve their own highlighted word; misses are mostly numbers inside a longer ruby unit (三時). Opening a word keeps a back stack (`ui.back`) so Back returns to the feed, lesson or word you came from. Esc or a tap elsewhere closes the sheet; any re-render closes it too.
- **Audio** uses the browser's `speechSynthesis` (free, device voices). The **Voice** picker on the Today tab lists the device's Japanese voices, with a male/female label for well-known names, and stores the choice in localStorage under `jp-study.voice`. That's per device on purpose, not in synced progress. If no Japanese voice turns up within 2s (or on `voiceschanged`), the speaker buttons hide.
- `initRemote()` syncs through `window.claude` (the claude.ai Artifact runtime) when it is available. On GitHub Pages it isn't, so the app quietly stays on localStorage and the footer says "saved in this browser only". `merge()` combines two states; keep it if the sync code stays.
- Scheduling: SM-2 style (`nextState`). Grades are Again/Hard/Good/Easy (0–3); reading reviews only use Good (2) and Again (0), so intervals go 2, 4, then ×ease (about 10, 25, 63 days…). Again resets the card (due in 10 minutes, and reading the extra sentence later in the feed moves it to two days out).
- The `/*TEST_HOOK*/` comment near the end of `app.js` is a marker for injecting test code. Leave it in place.

## Checking changes

Run the content checker, then `python3 tools/smoke_test.py` (headless Chromium: Learn new feed read to the end, reload keeps progress, lookup sheet, Kanji and Grammar pages, no console errors). Then, if the change is visual or about the flow, serve the folder from a subpath (for example, symlink it to `<root>/jp-study` and run `python3 -m http.server` in `<root>`) and check by hand: then serve the folder from a subpath (for example, symlink it to `<root>/jp-study` and run `python3 -m http.server` in `<root>`). Load it, run a reading review and a Learn new feed, read a lesson feed to the end, reload, and confirm progress persists.
